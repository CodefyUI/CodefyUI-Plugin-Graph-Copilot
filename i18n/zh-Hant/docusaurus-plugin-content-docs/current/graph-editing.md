# 它如何編輯圖

每則訊息，助手都會收到你已安裝節點型別的精簡**目錄**，加上目前圖的**快照**。連線前可查詢精確 schema；只有目錄名稱或 research 建議，不足以證明連接埠資訊。

## Ask 或 Edit

| 模式 | 可做的事 |
| --- | --- |
| **Ask** | 讀圖、查 schema、研究候選節點，以及明確要求結構驗證。不能送出圖修改，也不會自動修圖。 |
| **Edit**（預設） | 使用相同的唯讀工具，並對目前畫布套用圖操作批次。 |

每次執行（run）的模式固定。Ask 的**唯讀限制由執行層強制落實**：不向模型提供修改工具，即使模型仍呼叫它，也會拒絕。

## 五個工具

| 工具 | 用途 |
| --- | --- |
| `apply_graph_operations` | 透過 CodefyUI 外掛 API 套用非空、最多 100 個圖操作的批次。僅 Edit 可用。**一批 = 宿主的一個復原步驟。** |
| `get_current_graph` | 重新讀取畫布，包含對話期間的手動編輯。 |
| `get_node_schemas` | 用 `node_types` 查詢目錄中的精確節點型別，取得連接埠、必填／選填輸入，以及參數型別、預設值與範圍。 |
| `validate_graph` | 向伺服器要求唯讀的**結構驗證**，不執行圖。 |
| `research` | 平行研究最多四個獨立的 `questions`。只看 index 的子 agent 提供候選節點型別；實際連線前仍須查精確 schema。 |

## 操作與回執

支援的操作為 `add_node`、`connect`、`set_params`、`remove_node`、`remove_edge`、`clear_graph` 與 `auto_layout`。助手被要求：

- 使用目錄中精確的節點型別名稱，以及 schema 中精確的連接埠名稱；
- 連接它新增節點的每個必填輸入；
- 依型別與範圍設定參數；
- 在結構性的一批結尾加上一個 `auto_layout`；
- 除非你明確要求重來並確認，否則絕不清空圖。

格式錯誤、空白或過大的批次會在**送交宿主前整批拒絕**。格式合法的批次由 CodefyUI 驗證操作語義：未知型別、連接埠不相容、參數超出範圍會逐一被拒絕。已知失敗的操作會被略過並把錯誤回報給模型；成功的操作仍保留。這不是全有或全無的 transaction。

結果依 **`OpResult.index`** 配對，而不是依回傳陣列位置。缺少、重複或無法讀取的回執表示**副作用未知**，不能假定成功。`add_node` 的 ref 只在同一批內有效；之後的批次須使用回執 `refs` 對照表或 `get_current_graph` 提供的真實節點 ID。

## 確認清空

`clear_graph` 必須是該批次的**唯一操作**。混合清空與新增／連線／排版的批次會被拒絕且不修改圖，不會自動拆批。

- 面板要求一次性確認，綁定**執行 ID、工具呼叫及完整、未截斷的圖快照**。
- 送交宿主前再次檢查核准。若你確認期間圖有變化，確認失效且執行以 incomplete 結束；須取得新的確認。
- **Keep graph** 拒絕清空並結束執行。助手不得改用逐節點刪除來繞過拒絕。
- Stop、開啟 Settings 或 History、關閉面板，都會取消待確認的要求。

## 閱讀進度與結果

每個工具呼叫都會即時顯示成助手回覆下方的**階段列**，可展開查看結果內容。只有仍活動中的工具會轉圈；終止結果區分完成、錯誤、已取消、未執行及未知。停止或失敗時仍保留部分文字和回執。

執行的終止結果與結構驗證結果是**不同維度**：

| 執行狀態 | 意義 |
| --- | --- |
| `completed` | Agent 完成有界流程，沒有未解決的工具錯誤。不表示 pipeline 真正執行成功。 |
| `cancelled` | 執行已停止，包含拒絕清空；UI 顯示 **Stopped**。先前修改仍保留。 |
| `failed` | 請求、串流、初始化或宿主錯誤使執行結束。復原前先查看修改回執。 |
| `incomplete` | 無法確立完成，例如工具／修復上限耗盡，或回執／驗證不可用、過期。 |

| 結構狀態 | 意義 |
| --- | --- |
| `valid` | 受檢查的圖快照通過結構驗證。 |
| `invalid` | 驗證器回報結構問題。 |
| `unavailable` | 無法取得驗證，包含傳輸、HTTP 或回應格式錯誤；不代表圖一定無效。 |
| `not_run` | 尚未取得目前圖的驗證結果。唯讀回答可不經驗證而完成。 |
| `stale` | 圖已相對於受保護的快照改變；舊驗證結果不能代表目前圖。 |

> **結構驗證通過不是執行成功的證據。** 驗證檢查未知節點型別、缺少必填輸入、參數範圍等問題，不會跑 pipeline 或確立執行期成功。

## 有界的驗證與修復

只有**本次執行實際修改圖形**才會觸發結束前的自動驗證與修復。Ask 與唯讀回答不會修復既有問題；兩種模式下明確呼叫 `validate_graph` 也都維持唯讀。驗證仍檢查整個目前圖，不只檢查編輯過的子圖。

修復僅限本次執行已授權的修改。執行層會拒絕清空、改參數／移除無關既有節點，以及變動無關目標輸入的連線。仍可用所需的新節點與既有輸出補足受影響輸入；一般 `auto_layout` 可能重新排列畫布。

無效結構最多觸發兩次修復提示，工具回合上限為 16。驗證不可用不會觸發修復。最後檢查必須對應最後修改的快照；驗證期間圖改變時，結果為 stale 與 incomplete。上限耗盡、越界修復或問題未解決都是 incomplete，不是成功。

## Stop、接續與復原

- **Stop 阻止新的工具派送**，但不能中斷已在進行中的同步宿主修改，也不會撤銷已套用的變更。待執行的呼叫會得到明確的 cancelled／not-executed 結果，而不是永遠顯示執行中。
- 面板提供 **Retry** 時，僅允許宿主修改**從未派送**的嘗試。它重用原始要求與附件，不在可見或模型歷史中重複加入使用者要求；先前嘗試的結果仍保留。已拒絕的清空不會重試。
- **只要曾派送修改**，即使回報的操作全部失敗，也應使用 **Continue from current graph**，不要重播要求。這會新增一則接續指令並重新讀取即時圖，保留先前回執。副作用未知時也適用。
- 使用 **CodefyUI 的 Undo（Ctrl+Z）** 撤銷已套用的批次。一次執行可能包含多批，因而需要多個復原步驟；面板沒有 transaction、自動回滾或獨立 Undo API。

## 保留工作位置

開啟 Settings 或 History、關閉面板，都會停止活動中的執行，但聊天仍保持 mounted，保留目前對話的草稿與待送附件。這只限記憶體中的面板工作階段，不會在瀏覽器重新整理後持久保留草稿。停止的執行結束前不能切換或建立對話。晚到的結果只屬於原對話，不會覆寫另一個活動中的聊天。

儲存的工具呼叫只是脈絡，不是可重播的指令。送給模型的歷史視窗會保留完整 assistant／tool-call／result 群組，並排除舊聊天的孤立工具結果；詳見[架構](./architecture.md)。

起手提示只填入輸入框，讓你檢查後再送出。Enter 僅在輸入可送出時提交，Shift+Enter 換行，IME 組字不會送出。附件讀取錯誤持續可見，須移除錯誤附件才能送出。向上捲動會暫停自動跟隨；**Jump to latest** 可回到最新。
