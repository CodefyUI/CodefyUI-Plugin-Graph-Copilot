# 側欄、技能與工具

從 0.5.0 起，這個插件改名為 **Copilot**，是 CodefyUI 上的通用 agent。它一樣會建圖、跑實驗；現在還能依照 Agent Skills 與專案裡的 `AGENTS.md` 做事、在分頁中開啟圖與範例，並在你核准後讀取與提交專案檔案。插件 id 維持 `graph-copilot`，所以設定、對話與研究紀錄都會保留。

## 出現在哪裡

| 主程式 | 面板 | 技能與專案指令 |
| --- | --- | --- |
| 插件 API 6 的 CodefyUI（側欄、Agent Skills） | 從工具列開關打開的側欄；拖邊緣調整寬度（300–720 px） | 開啟 |
| CodefyUI 3.2.0（插件 API 5） | 跟以前一樣，右下角的浮動視窗 | 關閉：沒有技能頁面、技能工具，也不加進 prompt |
| CodefyUI 1.3.0 以上（插件 API 1） | 浮動視窗 | 關閉 |

插件載入時會偵測主程式支援哪些功能；舊版主程式沒有的功能就直接不出現，不會跳錯誤。

在側欄模式下，面板收起來時，工具列開關會標示 agent 的狀態：

| 狀態 | 何時 | 工具列標記 |
| --- | --- | --- |
| 需要你處理 | 有動作等你核准，或還沒設定模型供應商 | attention |
| 已完成 | 你沒在看的時候有一輪結束了 | done |
| 處理中 | 模型正在回覆，或工具正在執行 | working |
| 待命 | 其他情況 | 無 |

標題列用文字加符號（`!`、`✓`、`⚙`、`○`）顯示同樣的狀態。收起側欄不會中斷目前這一輪；關閉浮動視窗則跟以前一樣會中斷。

## 核准

清空畫布、一次移除大量節點（10 個以上，或至少 3 個且佔圖的一半以上）、執行圖、跑一組實驗、提交檔案，都要你核准。核准要求會以卡片出現在對話裡，寫明會發生什麼事與代價。跟圖有關的卡片會寫出作用在哪個分頁，若那個分頁是 Copilot 這一輪才開的也會註明。焦點預設在**取消**，按 Escape 也是取消；主要按鈕直接寫動作（「Run graph」「Commit 3 files」）。

核准由 agent 迴圈的程式碼檢查。技能、`AGENTS.md`、工具回傳的內容或模型自己的文字，都不能代替你核准，也不能跳過卡片。

卡片開著時，那一列工具顯示「等待你核准」；被拒絕的顯示「未執行」；只有真的做完的才用完成式。一輪失敗時，只會出現一個區塊：失敗原因、真實的錯誤訊息、哪些事沒有發生（「沒有改圖 · 尚未驗證」），然後是重試。你自己按的停止用中性色顯示，不當成錯誤。

在**詢問**模式下，會改變東西的工具不會提供給模型，模型硬要呼叫也會被拒絕；技能改變不了這一點。

## 技能

技能是一個資料夾，裡面有 `SKILL.md`（YAML front matter 寫 `name` 與 `description`，後面是說明），也可以附參考檔案。CodefyUI 會從專案的 `skills/`、使用者技能資料夾、插件與內建技能載入。打開**技能**頁面可以依來源瀏覽、逐一開關、閱讀說明與檔案，或從資料夾、壓縮檔、git 網址安裝。

- System prompt 只列出每個已啟用技能的名稱與描述，一個一行。任務符合某個技能時，agent 會呼叫 `load_skill` 讀完整說明。
- `read_skill_file` 只能讀這段對話中已經載入過的技能裡的檔案。路徑由 CodefyUI 檢查，插件不自己組路徑。
- 在訊息框輸入 `/` 可以挑技能（會隨下一則訊息送出）或指令：`/new`、`/clear`、`/skills`、`/settings`。
- 技能 front matter 裡的 `allowed-tools` **只顯示在技能頁面，不會實際限制工具**。技能也不能讓 agent 用到目前模式以外的工具。
- 技能裡的腳本永遠不會被執行。
- 安裝與刪除技能只能由你在技能頁面操作，agent 沒有安裝工具。CodefyUI 拒絕安裝時（例如沒有只綁在本機），技能頁面會照原文顯示 CodefyUI 的訊息，並隱藏安裝表單。

## 專案指令

開啟的專案若有 `AGENTS.md`，內容會加進 system prompt 的 **Project instructions**。它跟技能本文一樣放在標示清楚的區塊裡，並註明這是參考資料，不能改變上面的規則。工具回傳的內容一律以 tool 角色送給模型，不會拼進 system prompt。

## 工具

原本十個建圖、執行與實驗工具不變（見[Agent 如何編輯圖](./graph-editing.md)）。新增的工具如下：

| 工具 | 模式 | 需要 | 做什麼 |
| --- | --- | --- | --- |
| `load_skill` | 詢問與編輯 | Agent Skills | 讀技能說明與檔案清單；重複載入只回一句「已載入」 |
| `read_skill_file` | 詢問與編輯 | Agent Skills | 讀已載入技能中的一個檔案（最多 64 KB） |
| `list_tabs` | 詢問與編輯 | Workspace API（插件 API 5） | 列出開著的圖分頁與各自的節點數 |
| `open_graph` | 編輯 | Workspace API | 在新分頁開啟已儲存的圖；已經開著就直接回報 |
| `search_examples` | 詢問與編輯 | Workspace API | 搜尋主程式的範例圖 |
| `open_example` | 編輯 | Workspace API | 在新分頁開啟範例（不會蓋掉目前的畫布） |
| `project_status` | 詢問與編輯 | git 專案 | 目前分支與變更的檔案；`.env` 檔不列出 |
| `project_diff` | 詢問與編輯 | git 專案 | 單一檔案的 diff（最多 32 KB）；`.env` 檔一律拒絕 |
| `project_log` | 詢問與編輯 | git 專案 | 最近的提交 |
| `project_commit` | 編輯，需核准 | git 專案 | 只暫存列出的檔案，提交到目前分支 |

過長的結果會被截短並標示：技能本文與檔案 64 KB、diff 32 KB、清單 200 筆。diff 與提交紀錄會放在標示為不可信資料的引用區塊裡交給模型。儲存的對話只記下載入過的技能或技能檔案的參照，不存全文；對話繼續時 Copilot 會重新取得，取不到就告訴模型。瀏覽器無法完整儲存對話時，面板會提醒你。

`project_commit` 的核准卡片會列出每個檔案。它只暫存這些路徑（不會「全部加入」），拒絕 `.env` 檔、git 忽略的檔案，以及只暫存了一部分的檔案（請先在原始碼控制分頁把暫存處理完），合併、rebase 或有衝突時也拒絕，並在你核准後再檢查一次檔案。它不會推送、拉取或切換分支；這些請在 CodefyUI 的原始碼控制分頁自己操作。

## 語言

面板跟著 CodefyUI 的介面語言（英文或繁體中文），切換語言時會跟著換。
